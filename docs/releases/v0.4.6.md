# Gonimbus v0.4.6 Release Notes

**Release Date**: 2026-11-08
**Status**: Forward-compatible advisory control records, faster durable prefix queries, look-alike flag hints, and release provenance hardening

## Summary

v0.4.6 adds a forward-compatible `"advisory": true` envelope marker for future
control records in `transfer reflow` pipelines, prunes trailing segments during
durable `index query --pattern` prefix scans, appends actionable hints for
look-alike unknown CLI flags, and tightens release provenance and dependency
hygiene.

- **Advisory control-record envelope marker.** `transfer reflow` skips
  unrecognized future control records marked with top-level `"advisory": true`
  (outside recognized work, integrity, and error record families) without
  incrementing `invalid_inputs`, emits at most one `gonimbus.warning.v1`
  (`REFLOW_ADVISORY_RECORD_SKIPPED`) per distinct type (up to 16 types, with a
  single `REFLOW_ADVISORY_WARNING_CAP_REACHED` warning record if exceeded), and
  continues without aborting the batch. `content probe` stamps `"advisory":
true` on `gonimbus.content.probe.summary.v1`.
- **Durable prefix segment pruning.** `index query --pattern <glob>` stops
  opening and hashing segments once a segment's `MinRelKey` sorts strictly
  after the pattern's literal prefix (while still reading segments with
  inverted bounds).
- **Look-alike CLI flag hints.** Unknown `--profile`/`-p`, `--json` and
  `--count` flags on subcommands with different flag names or invocation shapes
  now append a targeted hint before the usage block, and `inspect` documents
  its default 100-object `--limit` cap.
- **Release provenance and immutable publication.** Release publication stages
  tagged public verification keys as release assets, verifies Decernor's
  SHA-256 before execution, uses an isolated `GNUPGHOME` for tag and anchor
  verification, and verifies GitHub release immutability on publish.
- **Security and dependency updates.** Updates `github.com/andybalholm/brotli`
  to v1.2.7 (`GO-2026-6888`), `github.com/klauspost/compress` to v1.20.2
  (`GO-2026-6865`), `github.com/go-chi/chi/v5` to v5.4.0,
  `github.com/go-jose/go-jose/v4` to v4.1.6, `golang.org/x/net` to v0.62.0,
  `golang.org/x/crypto` to `v0.58.1-0.20261009181718-2f1f834330b2` (cooled
  2026-10-09 commit), `golang.org/x/sys` to v0.49.0, `golang.org/x/sync` to
  v0.24.0, and `golang.org/x/text` to v0.43.0, and canonicalizes top-level
  `LICENSE` and `NOTICE`.

## Highlights

### Forward-compatible advisory control records (`"advisory": true`)

When `transfer reflow` reads a JSONL input stream, known record types
(`gonimbus.content.probe.summary.v1`, `gonimbus.reflow.input.v1`,
`gonimbus.index.object.v1`, and raw URI lines) dispatch first and are validated
by their existing parsers regardless of whether `"advisory"` is present; a
malformed known record is never skipped.

For other record types:

- Recognized work, integrity, and error record families (including
  `gonimbus.index.*`, `gonimbus.reflow.*`, `gonimbus.error.*`,
  `gonimbus.operation.*`, `gonimbus.selection.*`, `gonimbus.crawl.*`,
  `gonimbus.content.probe.v*`, and `gonimbus.content.head.*`) at an unknown
  version are refused even when marked `"advisory": true`.
- Unknown record types outside those families are skipped only when top-level
  `"advisory": true` is present (with exact lowercase envelope key names, no
  duplicate top-level envelope keys, and a lowercase ASCII record-type token),
  without incrementing `invalid_inputs`. `transfer reflow` emits at most one
  sanitized `gonimbus.warning.v1` record (`code:
"REFLOW_ADVISORY_RECORD_SKIPPED"`) per distinct skipped type, capped at 16
  distinct types per run (followed by a single `code:
"REFLOW_ADVISORY_WARNING_CAP_REACHED"` warning record when the scan ends if
  more than 16 distinct types were skipped), and continues processing object
  work.
- Unknown record types without `"advisory": true`, `"advisory": false`,
  non-boolean `"advisory"` values, or duplicate/case-variant envelope keys fail
  closed.
- `content probe` now stamps top-level `"advisory": true` on emitted
  `gonimbus.content.probe.summary.v1` records. Existing `v0.4.4` and `v0.4.5`
  consumers ignore that extra top-level field on the known summary type.

See
[Probe termination and process result](https://github.com/3leaps/gonimbus/blob/v0.4.6/docs/user-guide/streaming.md#probe-termination-and-process-result)
for the version-skew compatibility table.

### Durable `index query --pattern` segment pruning

Durable-v2 segments store sorted keys with per-segment `[MinRelKey, MaxRelKey]`
bounds in the snapshot manifest. Previously, `index query --pattern <glob>`
pruned segments whose `MaxRelKey` sorted before a literal pattern prefix, but
still opened and hashed segments whose `MinRelKey` sorted after the prefix.

`segmentMayMatch` now skips any segment whose `MinRelKey` sorts strictly after
the literal prefix without starting with that prefix. If a segment has inverted
bounds (`MinRelKey > MaxRelKey`), it is still opened and read rather than
skipped. Narrow prefix queries against multi-segment durable snapshots no
longer read or verify trailing segments past the matching key range.

### Look-alike CLI flag hints and `inspect` limit guidance

When an invocation passes `--profile`/`-p`, `--json` or `--count` to a
subcommand that uses a different flag or output contract, the CLI appends a
one-line hint to the unknown-flag error while still printing `Usage:`:

- `--profile` / `-p` on `index build` and `crawl` points to job-manifest
  provider configuration (`aws://bucket/prefix?profile=NAME`) or `AWS_PROFILE`;
  on `transfer reflow` it points to `--src-profile` and `--dest-profile`.
- `--json` on `index query`, `content head`, `content probe`, `inspect-pair`
  and `transfer reflow` notes that JSONL is already the default on stdout (or
  points to `--output-format`); on `stream head`, `stream get` and `stream put`
  it notes the framed-stream stdout contract.
- `--count` on `inspect` notes that `inspect` lists up to `--limit` objects
  (default `100`) and points to `--limit 0` with `jq -s 'length'` or
  `index query --count` against a local index.

### Release provenance, dependencies, and license hygiene

- **Release provenance and immutable publication.** Release publication stages
  tagged `gonimbus-minisign.pub` and `release-signing-keys.asc` alongside the
  checksum manifests and archives, verifies the Decernor helper binary against
  `DECERNOR_EXPECTED_SHA256`, runs GPG tag and anchor checks inside an isolated
  temporary `GNUPGHOME` with `GIT_NO_REPLACE_OBJECTS=1`, verifies GitHub
  `immutable: true` after publish, and provides `make release-verify` for
  offline bundle verification.
- **Security and dependency updates.** `github.com/andybalholm/brotli` is
  updated to `v1.2.7` (`GO-2026-6888`) and `github.com/klauspost/compress` to
  `v1.20.2` (`GO-2026-6865`), alongside `github.com/go-chi/chi/v5` `v5.4.0`,
  `github.com/go-jose/go-jose/v4` `v4.1.6`, `golang.org/x/net` `v0.62.0`,
  `golang.org/x/crypto` `v0.58.1-0.20261009181718-2f1f834330b2` (pinned to the
  cooled 2026-10-09 commit providing the advisory fix while the next tagged
  release remained inside the 7-day cooling window), `golang.org/x/sys`
  `v0.49.0`, `golang.org/x/sync` `v0.24.0`, and `golang.org/x/text` `v0.43.0`.
  CI container jobs run on `goneat-tools-runner-glibc:v0.5.14` (`goneat v0.6.7`,
  Go `1.26.10`).
- **Canonical Apache-2.0 `LICENSE` and `NOTICE`.** Top-level `LICENSE` contains
  the verbatim Apache License 2.0 text (`google/licensecheck` 100.00% match),
  and project copyright and attribution live in top-level `NOTICE`.

### Known limits

- `transfer reflow` fails closed on unknown record types that do not carry
  top-level `"advisory": true` and on any unknown version of a recognized work,
  integrity, or error record family even when `"advisory": true` is present.
  Older reflow consumers (`v0.4.4` and `v0.4.5`) still reject record types
  unknown to them even when `"advisory": true` is present.

## Release provenance

- Before importing a downloaded public key, establish the expected GPG signing
  key and minisign public-key fingerprint through an independently trusted
  maintainer channel. Follow the complete
  [release-verification guide](https://github.com/3leaps/gonimbus/blob/v0.4.6/docs/security/README.md).
- The tagged public verification material is
  [the OpenPGP key](https://github.com/3leaps/gonimbus/blob/v0.4.6/docs/security/release-signing-keys.asc),
  [the minisign public key](https://github.com/3leaps/gonimbus/blob/v0.4.6/docs/security/gonimbus-minisign.pub),
  and [the expected fingerprint anchors](https://github.com/3leaps/gonimbus/blob/v0.4.6/keys/expected-fingerprints.txt),
  and the public keys are also attached to the GitHub release as assets.
- Release tags are GPG-signed. After validating the public material against
  the committed anchors, verify with `git tag -v v0.4.6`.
- Checksum manifests are signed with minisign and PGP; the published assets are
  byte-identical to the signed set, and GitHub release immutability is
  verified at publication time.
- The tag workflow is read-only: it verifies the signed tag against the public
  pin committed in the tagged commit, builds, and hands the artifacts to the
  maintainer ceremony. It does not create the release.
