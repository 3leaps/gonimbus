# Gonimbus v0.4.4 Release Notes

**Release Date**: 2026-10-20
**Status**: Write receipts, probe outcomes, and listing integrity

## Summary

v0.4.4 makes copy and probe pipelines report what actually happened, and
makes index builds refuse a listing that ended early.

- **Terminal write receipts.** Terminal `gonimbus.reflow.v1` records can carry
  the destination's acknowledgement of each write: payload SHA-256, ETag,
  revision, and the known source last-modified time.
- **Probe outcomes.** `content probe` ends with one
  `gonimbus.content.probe.summary.v1` record, and a completed run with object
  data errors now exits **60** instead of **32**.
- **Listing integrity.** A listing page that reports more results without a
  usable continuation token fails the listing. An index build fails before
  sealing instead of attesting a partial inventory.
- **Release provenance.** Releases are built by a read-only tag workflow and
  published through a signed maintainer ceremony.

**Upgrade note:** scripts that match exit code 32 for a completed probe with
object data errors must handle 60. Code 32 still means a provider or
infrastructure failure.

## Highlights

### Terminal write receipts

Terminal reflow records optionally include `dest_sha256`, `dest_etag`,
`dest_version_id`, and `source_last_modified`. Skips, failures, dry runs, and
in-progress records do not claim a destination write. Unknown or unsafe
identifiers are omitted rather than partially redacted. Receipt construction
adds no provider requests.

These are transfer receipts: they report what the write acknowledged. They do
not establish independent read-back verification. `inspect-pair` passes them
through as upstream claims without changing its scope admission or HEAD-based
verdict. The v1 schema is unchanged and the fields are additive, so existing
consumers can ignore them. See
[Terminal write receipts](https://github.com/3leaps/gonimbus/blob/v0.4.4/docs/user-guide/reflow.md#terminal-write-receipts).

### Probe summary and exit codes

Handled `content probe` runs end with a summary record carrying input, task,
emitted, routing, error, and byte accounting, plus a `termination` and
`exit_code`:

| Termination             | Exit                                             |
| ----------------------- | ------------------------------------------------ |
| `completed`             | 0                                                |
| `completed_with_errors` | 60 (`EXIT_DATA_INVALID`), previously 32          |
| `failed`                | Provider failures remain 32; invalid input is 40 |
| `aborted`               | Nonzero cancellation result                      |

Updated reflow consumers accept the summary as control evidence, never as
object work. Upgrade the producer and consumer together, or filter only the
summary type for an older consumer. In a pipeline, use `set -o pipefail`,
save `PIPESTATUS`, and check the probe summary as well as the mover's exit
status. See
[Probe termination and process result](https://github.com/3leaps/gonimbus/blob/v0.4.4/docs/user-guide/streaming.md#probe-termination-and-process-result).

### Listings that end early fail

A listing page that says more results follow but returns no continuation token,
or a token that does not advance, now fails with
`provider.ErrIncompleteListing`. This applies to the S3 provider, scope and
shard prefix discovery, and the crawler for any provider. An index build fails
before sealing instead of recording a partial listing as complete, or looping
on a repeating token.

### Durable include refusals name the alternative

Durable builds accept only the default match include. The refusal now names
what to use instead: `index migrate-match-scope` for prefix-shaped includes,
`build.scope` for a wildcard in a middle path segment, and `--format sqlite`
otherwise. The durable index guide has a worked
[`date_partitions` example](https://github.com/3leaps/gonimbus/blob/v0.4.4/docs/user-guide/durable-index.md#wildcard-in-a-middle-path-segment)
for a wildcard segment followed by a date-shaped tail.

### Known limits

- Durable builds accept only the default match include. Other non-prefix
  patterns, excludes, and filters require `--format sqlite`.
- A discovered scope plan is compiled at build time and is not compared with
  the parent run. If discovery stops returning a partition, rows under it are
  retained rather than tombstoned, but they stay active without a fresh
  observation and the published coverage no longer lists their prefix. The
  receipt does not yet record the compiled plan.

### Also in this release

- A shared request budget holds its configured `rate_limit` when many workers
  wait at once. A wait that cannot start before the caller's deadline is
  refused.
- The job registry retries Windows sharing and lock violations reported as
  NTSTATUS codes.
- Build with Go toolchain `go1.26.9`. Dependencies are refreshed, including
  `golang.org/x/net` v0.60.0 and `go.opentelemetry.io/otel/sdk` v1.45.0 for
  published advisories.

## Library API

There are no breaking changes to the Stable embedded library API.

- `pkg/provider` adds the `ErrIncompleteListing` sentinel and optional
  `ResultPutter` and `MetadataAwareResultPutter` capabilities. The S3 provider
  implements result-bearing unconditional PUTs. Existing error-only interfaces
  remain, and providers without the new capabilities keep their existing
  fallback behavior.
- Experimental transfer uploads expose the full logical-payload SHA-256 and
  payload length after an acknowledged write. `CopyObjectWithReceipt` returns
  write handles and source-read timestamps when available.

## Release provenance

- Before importing a downloaded public key, establish the expected GPG signing
  key and minisign public-key fingerprint through an independently trusted
  maintainer channel. Follow the complete
  [release-verification guide](https://github.com/3leaps/gonimbus/blob/v0.4.4/docs/security/README.md).
- The tagged public verification material is
  [the OpenPGP key](https://github.com/3leaps/gonimbus/blob/v0.4.4/docs/security/release-signing-keys.asc),
  [the minisign public key](https://github.com/3leaps/gonimbus/blob/v0.4.4/docs/security/gonimbus-minisign.pub),
  and [the expected fingerprint anchors](https://github.com/3leaps/gonimbus/blob/v0.4.4/keys/expected-fingerprints.txt).
- Release tags are GPG-signed. After validating the public material against
  the committed anchors, verify with `git tag -v v0.4.4`.
- Checksum manifests are signed with minisign and PGP; the published assets are
  byte-identical to the signed set.
- The tag workflow is read-only: it verifies the signed tag against the public
  pin committed in the tagged commit, builds, and hands the artifacts to the
  maintainer ceremony. It does not create the release.
