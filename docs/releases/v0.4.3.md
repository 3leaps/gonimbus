# Gonimbus v0.4.3 Release Notes

**Release Date**: 2026-09-11
**Status**: Reuse a finished durable inventory

Gonimbus v0.4.3 has two operator stories, in this order:

1. **Reuse a finished durable inventory instead of listing the bucket again.**
   Listing a very large object store is the expensive, slow, and
   inconsistent step. If a complete durable snapshot already exists
   (sealed journals, packed segments, manifest, completion marker), current
   Gonimbus can take **exact custody** of that already-complete run and
   query it under current acquire and receipt contracts **without walking
   the live object store**. Recrawl remains available; it is not required
   to adopt current custody.
2. **Prove which inventory you used, and when that snapshot actually
   finished.** Exact acquire never follows `latest.json`. Query can emit a
   typed receipt. Snapshot completion time is the time the snapshot
   completed, distinct from later hub commit time.

Supporting: pinned durable deltas (`--proof-through-run`); `index doctor
--snapshot-dir` inspects a named acquired bundle and does not consult
ambient cache; bridge validation accepts a safe relative coverage prefix
with one terminal `/` without rewriting historical manifest bytes.

As in v0.4.0–v0.4.2, durable-v2 remains a full-fidelity **internal render**
for trusted operator and pipeline use — **not** a reduced-trust,
de-identified, or third-party publication format. Content digests are
**content-integrity / tamper-evidence** checksums, not statements of
author authenticity or provenance. SQLite remains a first-class
compatibility path (`--format sqlite` / `--format both`).

Operator walkthrough: [Durable Index Format](../user-guide/durable-index.md).

## Highlights

- **`index hub bridge-durable`** — copy one exact already-complete durable
  run into current hub custody. No source LIST, no overwrite. Directory-form
  coverage prefixes (one terminal `/`) are accepted in **validation only**.
- **`index acquire`** — materialize that named index-set and run from a
  read-only hub handle into a local acquired bundle. No hub listing. No
  `latest.json`.
- **Query receipts** — `index query --output-format receipt-jsonl-v1`
  ends with one terminal receipt so automation can prove set, run, and
  outcome.
- **Truthful snapshot completion** — completion time is when the snapshot
  finished, not when a later hub commit landed.
- **`index doctor --snapshot-dir`** — inspect that acquired dest; do not
  fall through to another copy of the same set in cache.
- **Pinned deltas** — exact `--index-set`, current `--run-id`, and
  `--since-run` / `--proof-through-run` without a live bucket walk.

## Operator quick path

```bash
# Reuse an already-complete durable run (no live-store listing)
gonimbus index hub bridge-durable \
  --source-hub-read-handle archive-read \
  --target-hub-publish-handle custody-publish \
  --index-set idx_<64-lowercase-hex> \
  --run-id run_<exact-id> \
  --identity-file /path/to/identity.json \
  --output-format custody-bridge-receipt-jsonl-v1

# Materialize that exact run locally
gonimbus index acquire \
  --hub-read-handle archive-read \
  --index-set idx_<64-lowercase-hex> \
  --run-id run_<exact-id> \
  --dest /var/lib/gonimbus/acquired/that-run

# Prove the query ran against that dest
gonimbus index query \
  --snapshot-dir /var/lib/gonimbus/acquired/that-run \
  --count \
  --output-format receipt-jsonl-v1

# Inspect that dest, not ambient cache
gonimbus index doctor --snapshot-dir /var/lib/gonimbus/acquired/that-run
```

## Boundary framing

Do not treat acquire or bridge as a live-bucket discovery tool. Do not
retry without receipts, parse human query output as proof, or fall back to
listing the source bucket when a receipt is missing. Durable-v2 is not a
publication format for reduced-trust third parties.

## Upgrade

```bash
go install github.com/3leaps/gonimbus/cmd/gonimbus@v0.4.3
```

No recrawl of existing durable runs is required. Existing durable and
SQLite artifacts are read as-is. Downstream inventory consumers that pin
an approved binary should admit `v0.4.3` explicitly
(`gonimbus version --extended`).
