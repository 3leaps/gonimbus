# Gonimbus v0.4.5 Release Notes

**Release Date**: 2026-10-21
**Status**: Go 1.26.10 minimum, quieter stderr, single-source release tag

## Summary

v0.4.5 raises the minimum Go toolchain, keeps stderr for real problems, and
tightens how the release tooling selects a tag.

- **Go 1.26.10 minimum.** gonimbus builds with Go toolchain `go1.26.10`, to
  ensure secure operation.
- **Quieter stderr.** Commands against AWS S3 no longer print an SDK checksum
  debug line, and runtime failures no longer append the usage block.
- **Release tag from one variable.** Release tooling reads the tag only from
  `GONIMBUS_RELEASE_TAG` and checks it against `VERSION` before any
  tag-consuming step.

No commands, flags, record schemas or exit codes change in this release.

## Highlights

### Go 1.26.10 minimum

The module selects toolchain `go1.26.10` by default, and CI and release
workflows pin `actions/setup-go` to `1.26.10`. The module `go` directive stays
`1.26.0`, so an older local toolchain is not refused outright, but builds below
`go1.26.10` are not supported. If you build from source with
`GOTOOLCHAIN=local`, use Go 1.26.10 or newer.

### stderr carries only real problems

Scripts that treat stderr as a signal no longer see two kinds of noise:

- **SDK checksum line.** Ranged reads against AWS S3 carry no full-object
  checksum, and the AWS SDK logged
  `Response has no supported checksum. Not validating response payload.` at
  default verbosity. gonimbus now suppresses that line for every S3 client, as
  it already did for S3-compatible endpoints. gonimbus verifies payloads with
  its own hashing, and the SDK still validates any response that carries a
  supported checksum.
- **Usage block.** Usage prints only for invocation errors: unknown flags,
  invalid values, wrong argument counts and missing required flags. A runtime
  failure, such as a `content probe` run that completes with errors (exit 60),
  returns its error and exit code without the usage block. `-h`, `help` and
  shell completion are unchanged.

### Release tag from one variable

Release `make` targets read the tag only from `GONIMBUS_RELEASE_TAG`. Every
`release-*` goal refuses to start while the generic `RELEASE_TAG` is set from
any source, including an empty value. The download, draft, sign, upload and
publish targets require the tag to match `VERSION` and the app identity, and
verify the published tag only after that check. After a version bump on
`main`, run the remaining release steps from a checkout of the tagged commit.

### Documentation

- [Terminal write receipts](https://github.com/3leaps/gonimbus/blob/v0.4.5/docs/user-guide/reflow.md#terminal-write-receipts)
  describe what `dest_etag` holds per destination. S3 is the response ETag
  without quotes, and is not an MD5 for multipart uploads. GCS is the returned
  ETag. On `file://` it is a size, mtime and mode version token, not a content
  digest; use `dest_sha256` for content.
- The `index build --json` receipt, `gonimbus.index.build_result.v1`, is
  documented as a standalone document with top-level `type`, `schema_version`
  and `status`, not a `{type, data}` stream record. See
  [steady-state index operations](https://github.com/3leaps/gonimbus/blob/v0.4.5/docs/user-guide/steady-state-index-operations.md).

### Known limits

- `transfer reflow` refuses record types it does not recognize. Upgrade probe
  producers and reflow consumers together, or filter control records for an
  older consumer.

## Library API

There are no changes to the Stable embedded library API.

## Release provenance

- Before importing a downloaded public key, establish the expected GPG signing
  key and minisign public-key fingerprint through an independently trusted
  maintainer channel. Follow the complete
  [release-verification guide](https://github.com/3leaps/gonimbus/blob/v0.4.5/docs/security/README.md).
- The tagged public verification material is
  [the OpenPGP key](https://github.com/3leaps/gonimbus/blob/v0.4.5/docs/security/release-signing-keys.asc),
  [the minisign public key](https://github.com/3leaps/gonimbus/blob/v0.4.5/docs/security/gonimbus-minisign.pub),
  and [the expected fingerprint anchors](https://github.com/3leaps/gonimbus/blob/v0.4.5/keys/expected-fingerprints.txt).
- Release tags are GPG-signed. After validating the public material against
  the committed anchors, verify with `git tag -v v0.4.5`.
- Checksum manifests are signed with minisign and PGP; the published assets are
  byte-identical to the signed set.
- The tag workflow is read-only: it verifies the signed tag against the public
  pin committed in the tagged commit, builds, and hands the artifacts to the
  maintainer ceremony. It does not create the release.

```bash
brew install 3leaps/tap/gonimbus                      # macOS Apple Silicon, Linux
go install github.com/3leaps/gonimbus/cmd/gonimbus@v0.4.5
```

```powershell
scoop bucket add 3leaps https://github.com/3leaps/scoop-bucket
scoop install gonimbus
```
