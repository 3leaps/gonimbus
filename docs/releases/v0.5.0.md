# Gonimbus v0.5.0 Release Notes

**Release Date**: 2026-11-11
**Status**: `durable-index/v0` contract adoption and plan safeguards, `parquet-inventory/v0` ZSTD segments with legacy dual-read and portable relative markers, truthful dot-segment policy and per-run engine provenance, discovered `segments` build scopes and offline `migrate-match-scope`, and Gen-2.1 release ceremony refinements

## Summary

v0.5.0 adopts the `durable-index/v0` contract (`ADR-0017`, `DDR-0004`) across
durable index planning, segment emission, and verification; enforces fail-closed
`scope_loss` admission on successor durable builds unless an explicit pinned
acknowledgment is supplied; switches durable segment writes to
`parquet-inventory/v0` with `ZSTD` compression (~3.2× smaller segments) while
preserving full dual-read compatibility with existing `0.4.x` (`durable-v2`)
indexes and adding portable relative marker paths; records truthful
`include_hidden: true` durable set identity, `dot_segment_policy`,
`dot_segment_rows`, and per-run `gonimbus_version` / `gonimbus_commit` /
`gonimbus_vcs_modified` provenance; introduces `build.scope.type: segments`
(`ADR-0009`) and offline discovered-scope proposals in
`index migrate-match-scope`; and refines the release ceremony to Gen-2.1.

- **`durable-index/v0` plan canonicalization, `plan_digest`, and `scope_loss`
  safeguards.** Vendors and pins the upstream `durable-index/v0` contract
  closure (`segmented-snapshot/v0`, `coverage-attestation/v0`,
  `data-artifact/v0`, and `durable-index/v0` from `3leaps/crucible` `v0.2.9`)
  under `internal/contracts/durableindex/v0/upstream/` (`make
contract-fixture-integrity`). `pkg/durableindex`, `pkg/indexbuild`, and
  `internal/indexsubstrate` compile canonical `unicode-prefix/v0` prefix plans,
  compute the length-framed `durable-index/v0/plan\0` SHA-256 `plan_digest`,
  compare proposed plans against the verified parent publication by raw UTF-8
  byte-prefix containment, and refuse unexplained prefix coverage reductions
  (`scope_loss`) on `--format durable` and `--format both` (emitting a stderr
  warning on standalone `--format sqlite`). Intentional scope reductions require
  all four `--acknowledge-scope-loss-{parent,plan,by,at}` flags binding
  `(parent_manifest_sha256, proposed_plan_digest, actor, at)`, persisted across
  journal recovery along with `counts.retained_unobserved_rows`.
- **`parquet-inventory/v0` ZSTD segment emission, legacy `0.4.x` dual-read, and
  portable relative markers.** Durable index builds now emit `DDR-0004`
  `parquet-inventory/v0` segments compressed with `ZSTD` (and support
  `UNCOMPRESSED` on read), featuring nested `revision`,
  `first_seen`/`last_seen`/`last_changed`, optional `deleted`, a 3-level
  revision-bound `enrichments` LIST, and fixed 9-digit `.000000000Z` UTC
  timestamps. `pkg/indexreader` and `internal/indexsubstrate` retain full
  same-FD dual-read compatibility with `0.4.x` (`durable-v2`) flat Snappy
  segments: the `128 MiB` whole-member uncompressed byte ceiling applies
  strictly to `parquet-inventory/v0` segments while legacy `durable-v2` segments
  allow up to `1 GiB` across the segment so 250k-row `0.4.x` segments (~164 MiB
  uncompressed total) read cleanly. `complete.json` (`v2`) and `latest.json`
  (`v1`) add slash-normalized relative marker fields (`manifest_rel_path`,
  `segment_rel_dir`, `complete_rel_path`) alongside primary paths so `v0.5.0+`
  readers resolve copied or relocated index directories locally while `<= v0.4.7`
  readers continue reading via the primary paths.
- **Truthful dot-segment policy (`include_hidden: true`), `dot_segment_rows`,
  and per-run engine provenance.** Confirmed-complete durable index builds
  (`--format durable` and `--format both`) ingest all enumerated keys in scope,
  including keys with `.`-prefixed path segments (`dot_segment_policy:
"include"`), and record `"include_hidden": true` in `identity.json` (producing
  a distinct `v0.5.0` `index_set_id` rather than implicitly carrying forward a
  `0.4.x` set identity that excluded dot-segments). Both
  `gonimbus.index.manifest.v1` (`counts.dot_segment_rows`) and
  `gonimbus.index.build_result.v1` report `dot_segment_policy` and
  `dot_segment_rows` (active non-tombstone rows whose `rel_key` has at least one
  `/`-separated segment starting with `.`), and `manifest.json`,
  `complete.json`, and `gonimbus.index.build_result.v1` record per-run
  `gonimbus_version`, `gonimbus_commit`, and `gonimbus_vcs_modified` provenance.
- **Discovered `segments` build scope (`ADR-0009`) and offline
  `index migrate-match-scope`.** Ratifies `ADR-0008`, `ADR-0009`, and `DDR-0001`
  (`Accepted`). Adds `build.scope.type: segments` (`pkg/scope`) for partitioned
  key layouts with non-date literal or discovered middle segments and a terminal
  subtree (for example `tenant=*/table=orders/**`), sharing bounded delimiter
  listing and pagination safeguards with `date_partitions` (`MaxSegmentsTemplateDepth = 16`,
  `MaxDiscoveredPrefixesPerLevel = 10,000`, `MaxCompiledScopePrefixes = 65,536`)
  without changing existing `date_partitions` identity hashes. Extends
  `gonimbus index migrate-match-scope` with `--propose-discovered-scope` and an
  optional `discovered_scope_proposal` block on the migration audit record to
  generate a skeleton `date_partitions` or `segments` configuration from
  mid-path wildcard `include` globs without contacting any storage provider.
- **Gen-2.1 release ceremony refinements and tooling updates.** Updates
  `scripts/release-publish.sh` to the verified 1+1 download pattern, adds
  staged-tag verification (`--staged-prefix`), `noclobber` + expected
  tag-object/commit binding in `release-record-anchor.sh`, `<tag>.txt` + 3-line
  attribution footer checks in `release-prepare-tag-message.py`, worktree-aware
  `GONIMBUS_GPG_HOMEDIR` containment, and offline `jq-portability`,
  `release-write-guards`, and `release-promotion-recovery` test suites (`make
release-tooling-test`), and pins `goneat v0.6.8` and
  `goneat-tools-runner-glibc:v0.5.15`.

## Highlights

### `durable-index/v0` plan safeguards and `scope_loss` admission

In `v0.5.0`, durable index builds compile their resolved listing scope into a
canonical `unicode-prefix/v0` plan and compute a length-framed SHA-256
`plan_digest` (`durable-index/v0/plan\0...`). When a successor build runs
against an existing index set:

- `gonimbus` compares the proposed plan against the verified parent publication
  by raw UTF-8 byte-prefix containment (`baseline_not_compared`, `no_loss`,
  `loss_acknowledged`, or `scope_loss`).
- If any parent prefix is no longer covered by the proposed plan on
  `--format durable` or `--format both`, publication fails closed with
  `scope_loss` before writing a new `complete.json` or advancing `latest.json`.
  (Standalone `--format sqlite` builds emit a structured `scope_loss` warning on
  stderr.)
- When a scope reduction is intentional, operators must supply all four
  `--acknowledge-scope-loss-{parent,plan,by,at}` flags binding the
  acknowledgment to the exact parent manifest SHA-256, proposed `plan_digest`,
  actor identifier, and 9-digit UTC timestamp (`YYYY-MM-DDTHH:MM:SS.nnnnnnnnnZ`):

  ```bash
  gonimbus index build --job job.yaml \
    --acknowledge-scope-loss-parent <parent-manifest-sha256> \
    --acknowledge-scope-loss-plan <proposed-plan-digest-sha256> \
    --acknowledge-scope-loss-by <actor> \
    --acknowledge-scope-loss-at 2026-11-11T18:00:00.000000000Z
  ```

  The sealed acknowledgment and `counts.retained_unobserved_rows` persist
  through journal recovery.

- `pkg/indexreader` re-verifies that `latest.json` resolves to the caller's
  admitted `set_id` on open, and `captureVerifiedParent` fails closed if
  `latest.json` references a missing `complete.json`.

### `parquet-inventory/v0` ZSTD segments, legacy `0.4.x` dual-read, and portable markers

- **Physical segment format (`parquet-inventory/v0`):** New durable runs write
  `DDR-0004` Parquet segments compressed with `ZSTD`, reducing typical segment
  size by ~3.2× compared to `0.4.x` flat Snappy segments while enforcing strict
  `(namespace, key)` primary-key order, 9-digit `.000000000Z` UTC timestamps,
  and revision-bound `enrichments`.
- **Dual-read compatibility with `0.4.x` (`durable-v2`):** Existing `0.4.x`
  durable index sets and runs remain directly readable by `v0.5.0` without
  rebuild or migration. `parquet-inventory/v0` segments enforce a `128 MiB`
  whole-member uncompressed byte ceiling (`DefaultMaxParquetDecompressedBytes`,
  summed across all column chunks and row groups in the member), whereas legacy
  `durable-v2` segments use a `1 GiB` whole-segment uncompressed byte ceiling
  (`LegacyMaxParquetDecompressedBytes`) to accommodate `0.4.x` 250k-row Snappy
  segments (~164 MiB uncompressed total).
- **Portable relative markers (`complete.json` and `latest.json`):** Published
  `complete.json` markers now carry `manifest_rel_path` (`"manifest.json"`) and
  `segment_rel_dir` (`"."` in the CLI run layout where segments sit beside
  `complete.json`, or a layout-dependent relative directory such as `"segments"`
  when segments live in a subdirectory), and `latest.json` carries
  `complete_rel_path` (`"runs/<run_id>/complete.json"`), alongside the primary
  `manifest_path`, `segment_dir`, and `complete_path` fields. `v0.5.0+` readers
  prefer the relative fields when present (after verifying containment within
  the marker directory), so an index set copied or moved to another directory on
  the same or another host reads and builds against its own local files even if
  the source directory still exists on disk, while `<= v0.4.7` readers continue
  using the primary paths.

### Truthful dot-segment policy (`include_hidden: true`), `dot_segment_rows`, and run provenance

- **Confirmed-complete durable scopes include dot-segments:** Under
  `durable-index/v0` invariant `I3` (`enumerated_key_omitted`), a scope claiming
  complete enumeration coverage cannot silently omit enumerated keys whose path
  contains a `.`-prefixed segment (such as `.well-known/assetlinks.json` or
  `a/.hidden/file.parquet`). Durable builds (`--format durable` and
  `--format both`) now ingest all enumerated keys in scope (`dot_segment_policy:
"include"`) and record `"include_hidden": true` in `identity.json`.
- **Set identity boundary across `0.4.x` → `0.5.0`:** Because `identity.json`
  for a durable build now records `"include_hidden": true` (and `v0.5.0` removes
  implicit cross-version `index_set_id` carry-forward when `identity.json`
  differs), running `v0.5.0` against a scope previously indexed by `0.4.x`
  derives a new `v0.5.0` `index_set_id` (`idx_...`) and starts a fresh `v0.5.0`
  baseline set while leaving the existing `0.4.x` set untouched and readable.
  Within `v0.5.0`, successor builds carry `index_set_id` forward across runs.
- **Explicit dot-segment row accounting:** Both `gonimbus.index.manifest.v1`
  (`counts.dot_segment_rows` + top-level `dot_segment_policy`) and
  `gonimbus.index.build_result.v1` (`dot_segment_policy` + `dot_segment_rows`)
  report the exact count of active (non-tombstone) rows in the snapshot whose
  `rel_key` has at least one `/`-separated segment starting with `.`. Names such
  as `_SUCCESS` are not dot-segments and are not counted in `dot_segment_rows`.
- **Per-run build provenance:** Every durable run records `gonimbus_version`,
  `gonimbus_commit`, and `gonimbus_vcs_modified` in `manifest.json`,
  `complete.json`, and the `gonimbus.index.build_result.v1` JSON receipt,
  allowing downstream consumers to distinguish official immutable release builds
  from local or modified-tree builds in run artifacts as well as via
  `gonimbus version --json --extended`.

### Discovered `segments` build scope (`ADR-0009`) and offline `index migrate-match-scope`

- **`build.scope.type: segments`:** Supports partitioned object layouts that mix
  fixed literal segments and delimiter-discovered wildcard segments before a
  terminal `**` subtree (both `discover.segments` template syntax such as
  `tenant=*/table=orders/**` and explicit `constraints` segment lists).
  Discovery uses bounded delimiter listing (`MaxSegmentsTemplateDepth = 16`,
  `MaxDiscoveredPrefixesPerLevel = 10,000`, `MaxCompiledScopePrefixes = 65,536`)
  and compiles into a canonical `unicode-prefix/v0` prefix plan. Existing
  `date_partitions` configurations and their `scope_hash` / `index_set_id`
  values are unchanged.
- **Offline `gonimbus index migrate-match-scope`:** Inspects legacy
  `match.include` patterns offline (zero provider calls) and emits a
  `gonimbus.scope.match_prefix_migration.v1` audit record with `classification`
  set to `convertible`, `already_compatible`, `already_migrated`, or `refused`.
  When `match.include` contains a single mid-path wildcard followed by a
  date-shaped or literal segment tail, default `prefix_list` migration
  classifies it as `refused` (`non_prefix_include`) and attaches a
  `discovered_scope_proposal` preview; passing `--propose-discovered-scope`
  promotes that pattern to `convertible` and emits a ready-to-edit
  `date_partitions` or `segments` YAML scope skeleton.

See
[Durable Index Format](https://github.com/3leaps/gonimbus/blob/v0.5.0/docs/user-guide/durable-index.md),
[Discovered-Segments Build Scope (`ADR-0009`)](https://github.com/3leaps/gonimbus/blob/v0.5.0/docs/architecture/adr/ADR-0009-discovered-segments-build-scope.md),
[Durable storage architecture](https://github.com/3leaps/gonimbus/blob/v0.5.0/docs/architecture/durable-storage.md),
and
[Canonical-state conformance](https://github.com/3leaps/gonimbus/blob/v0.5.0/docs/architecture/canonical-state-conformance.md).

### Pinned `0.4` minor-line package retention (`gonimbus@0.4` / `gonimbus-0.4`)

Per the minor-line retention rule established in `v0.4.7`, cutting `v0.5.0`
preserves the terminal `0.4.x` release (`v0.4.7`) as a pinned minor-series
package in both distribution channels using the exact raw `v0.4.7` release asset
URLs and `SHA256SUMS` digests:

- **Homebrew (`3leaps/homebrew-tap`):** `Formula/gonimbus@0.4.rb`
  (`keg_only :versioned_formula`, installable via
  `brew install 3leaps/tap/gonimbus@0.4`) alongside `Formula/gonimbus.rb`
  (`v0.5.0`).
- **Scoop (`3leaps/scoop-bucket`):** `bucket/gonimbus-0.4.json` (installable via
  `scoop install 3leaps/gonimbus-0.4`) alongside `bucket/gonimbus.json`
  (`v0.5.0`).

## Library API

There are no breaking changes to the Stable embedded library API. New
`pkg/durableindex` package is added in the Experimental tier.

## Release provenance

- Before importing a downloaded public key, establish the expected GPG signing
  key, exact signing subkey, and minisign public-key fingerprint through an
  independently trusted maintainer channel. Follow the complete
  [release-verification guide](https://github.com/3leaps/gonimbus/blob/v0.5.0/docs/security/README.md).
- The tagged public verification material is
  [the OpenPGP key](https://github.com/3leaps/gonimbus/blob/v0.5.0/docs/security/release-signing-keys.asc),
  [the minisign public key](https://github.com/3leaps/gonimbus/blob/v0.5.0/docs/security/gonimbus-minisign.pub),
  [the pinned signing subkey](https://github.com/3leaps/gonimbus/blob/v0.5.0/config/release/signing-subkey.txt),
  and [the expected fingerprint anchors](https://github.com/3leaps/gonimbus/blob/v0.5.0/keys/expected-fingerprints.txt),
  and both public keys and both fingerprint anchor files are attached to the
  GitHub release as assets.
- Release tags are GPG-signed. After validating the public material against
  the committed anchors, verify with `git tag -v v0.5.0`.
- Checksum manifests are signed with minisign and PGP; the published assets are
  byte-identical to the signed set, GitHub release immutability is verified at
  publication time (`make release-stage-published`), and Go proxy, Homebrew tap,
  and Scoop bucket parity are verified against the staged release (`make
release-verify-registries`).
- The tag workflow is read-only: it verifies the signed tag against the public
  pin committed in the tagged commit, builds, and hands the artifacts to the
  maintainer ceremony. It does not create the release.

## Install

```bash
brew install 3leaps/tap/gonimbus                      # macOS Apple Silicon, Linux (v0.5.0)
brew install 3leaps/tap/gonimbus@0.4                  # pinned terminal v0.4.7 minor line
sfetch --repo 3leaps/gonimbus --tag v0.5.0 --dest-dir ~/.local/bin
go install github.com/3leaps/gonimbus/cmd/gonimbus@v0.5.0
```

```powershell
scoop bucket add 3leaps https://github.com/3leaps/scoop-bucket
scoop install gonimbus                                # latest stable (v0.5.0)
scoop install gonimbus-0.4                            # pinned terminal v0.4.7 minor line
```

## Verification

- `gonimbus version --json --extended` reports `"version":"0.5.0"`.
- Existing `0.4.x` (`durable-v2`) durable and SQLite index artifacts remain
  readable as-is; running a new durable `index build` under `v0.5.0` derives a
  truthful `include_hidden: true` `v0.5.0` set identity (`idx_...`) and writes
  `parquet-inventory/v0` ZSTD segments without modifying any existing `0.4.x`
  index set.
- Downstream inventory consumers that pin an approved binary or inspect durable
  build receipts (`gonimbus.index.build_result.v1`) must admit `v0.5.0`
  explicitly.
