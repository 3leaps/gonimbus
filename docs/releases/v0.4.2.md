# Gonimbus v0.4.2 Release Notes

**Release Date**: 2026-08-13
**Status**: Library Reflow Data Plane + Independent Source/Dest Admission

Gonimbus v0.4.2 has two operator stories, in this order:

1. **The library reflow engine is the data plane.** Concurrent record-stream
   execution, memory admission, collision, durability, provenance sidecars,
   S3-compatible positional sources, and budgeted partitioned work live in
   `pkg/reflow`. The CLI is an adapter (ADR-0006). A standing dual-path parity
   gate holds engine and CLI-pool behavior together.
2. **Object-store and heterogeneous copies admit source and dest independently.**
   Source-read and dest-write no longer share one global permit for the whole
   Get→Put. Dest work can run above source under a recorded, pool-realizable
   ceiling, still bounded by `--parallel`, memory, file-descriptor, IfAbsent,
   and throttle clamps.

Connection pools follow the already-admitted N on parallel verbs. Index jobs
gain lease reclaim, parallel durable journal lanes, and `plan-stalled` /
`recover-stalled`. File destinations publish IfAbsent landings atomically so a
hard interrupt does not leave a visible truncated final.

As in v0.4.0 and v0.4.1, durable-v2 remains a full-fidelity **internal render**
for trusted operator and pipeline use — **not** a reduced-trust, de-identified,
or third-party publication format. Content digests are **content-integrity /
tamper-evidence** checksums, not statements of author authenticity or
provenance. SQLite remains a first-class compatibility path (`--format sqlite`
/ `--format both`).

Operator walkthroughs: [Reflow](../user-guide/reflow.md),
[Concurrency and Throughput](../user-guide/concurrency-and-throughput.md).

## Highlights

- **Library engine executes live copies** — stdin `gonimbus.reflow.input.v1`
  copies with `s3://` sources and an object-store destination dispatch to
  `pkg/reflow` again (the v0.4.1 CLI-pool narrowing is removed) behind a
  standing behavioral parity gate. Run records carry `execution_path`
  (`engine` | `cli-pool`) plus requested, effective, and observed concurrency
  as separate fields. File destinations, file-tree sources, GCS positional
  sources, and `index.object.v1` stdin still report `cli-pool`.
- **`--memory-budget` and a memory admission ledger** — the transfer states
  the memory that governs retry buffering and concurrency sizing (not total
  process memory). The lowest detected memory candidate binds; copy buffers
  reserve from the budget before any provider action. Pressure fields report
  where a run waited on admission; the effective ceiling is not raised by
  observed pressure.
- **Collision, durability, provenance, and positional sources in the engine**
  — keyed durability for partitioned work, source-revision-bound resume,
  engine-authored `gonimbus.provenance.v1` sidecars, and S3-compatible
  positional sources share the same concurrency and checkpoint contracts.
- **Independent source/dest admission** (#191, #192) — a phase-split copy
  gate issues per-domain permits on both execution paths. Dest admission
  tracks twice adaptive `current` (source stays at `current`), hard-clamped
  to a recorded, pool-realizable dest ceiling of twice the effective ceiling
  (default multiplier 2), without raising the operator `--parallel` request.
  Honesty checks assert the recorded dest policy, not a hard-coded factor.
  Optional `gonimbus.reflow.object_path_stage_stats.v1` is a diagnostic, not a
  throughput claim.
- **Connection pools follow admitted N** — Stable `ResolveConnectionPool`
  maps already-authorized concurrent work to HTTP idle-retention and per-host
  caps. Index, crawl, enrich, transfer, content, tree, and reflow constructions
  use it; single-shot paths stay on SDK defaults. This is not a field-throughput
  claim.
- **Index job leases and stalled recovery** (#185) — stale set-authority
  leases are detected and reclaimed; a completed holder drops its lease.
  `index jobs plan-stalled <job_id>` reports a recovery action;
  `recover-stalled <job_id>` is dry-run by default and mutates only with
  `--confirm`.
- **Parallel durable crawl journal lanes** (#182) — durable `index build`
  can crawl multi-entry plans across independent journal lanes and still
  publish one consistent snapshot. Matcher-derived single-entry plans stay
  single-lane.
- **Atomic file IfAbsent publish** (#190) — file destinations stage then
  no-replace-link so a hard interrupt mid-write does not leave a visible
  partial final object.

## What operators should do differently

Most v0.4.1 workflows are unchanged. Live stdin `gonimbus.reflow.input.v1`
copies with S3-compatible sources and object-store destinations dispatch to
the library engine (the v0.4.1 CLI-pool narrowing is removed). `--parallel`
remains a requested ceiling, not a guaranteed worker count. Remaining
CLI-pool forms report `execution_path: cli-pool`.

```bash
# Live reflow — engine path for reflow.input.v1 + s3:// source; --parallel is a requested ceiling
gonimbus transfer reflow --stdin --dest 's3://dest-bucket/prefix/' \
  --rewrite-from '{key}' --rewrite-to '{key}' --parallel 32

# Optional memory bound for retry buffers + concurrency sizing
gonimbus transfer reflow --stdin --dest 's3://dest-bucket/prefix/' \
  --memory-budget 8GiB --parallel 32

# Managed index job: plan a stalled recovery (no authority mutation)
gonimbus index jobs plan-stalled job_...

# Apply that recovery (confirm-gated; omit --confirm to dry-run recover)
gonimbus index jobs recover-stalled job_... --confirm
```

`--memory-budget` is refused before any provider construction if the value is
out of range (64 MiB–4 TiB). A budget above the detected memory limit is
clamped and recorded as `operator_clamped_to_limit`.

Dest-biased admission is automatic on object-store / heterogeneous copies.
There is no new operator flag to "turn on dual-domain." Integrity clamps
(IfAbsent, whole-copy memory, throttle feedback) still bind.

### Compatibility notes

- No format or schema break. Existing durable-v2 and `index.db` artifacts
  remain readable.
- File destinations, file-tree sources, GCS positional sources,
  `index.object.v1` stdin, quarantine collision mode, `--preserve-mode`,
  and non-default `--on-source-failure` still take the CLI-pool path
  (`execution_path: cli-pool`).
- `query --since-run`, `stats --prefixes`, and full `--resume-run` recovery
  remain SQLite-only — use `--format sqlite` or `--format both`.
- Experimental `GONIMBUS_REFLOW_ELIDE_RAW_EXEC_SAVEPOINTS` stays default off
  and is not recommended for production.
- Windows FD probe still serializes copies (`resource_capped:fd`).
- Hard process-kill crash windows and multi-process shared checkpoint roots
  remain unclaimed; run one transfer per checkpoint at a time.

## Internal-render framing (important)

Durable-v2 remains a full-fidelity **internal render** for trusted operator and
pipeline use. It is **not** a reduced-trust, de-identified, or third-party
publication format. A durable hub export is not a disclosure-controlled share
format; rendering a durable index for any reduced-trust or third-party context
is out of scope for this format.

## Integrity, not authenticity

The content digests carried by durable manifests and segments (and by sealed
journals) are **content-integrity / tamper-evidence** checksums. They detect
corruption or modification of the bytes they cover. They are **not** statements
of author authenticity or provenance, and no recovery, journal, or durability
claim in this release should be read as certifying who produced a record.

## Upgrade notes

```bash
go install github.com/3leaps/gonimbus/cmd/gonimbus@v0.4.2
```

1. Install v0.4.2. Existing durable and SQLite artifacts are read as-is; no
   migration is required.
2. Expect engine-eligible live stdin reflow (`gonimbus.reflow.input.v1` +
   `s3://` source + object-store dest) to report `execution_path: engine`.
   Requested `--parallel`, the effective ceiling, and observed max-active
   remain separate fields. Other live forms still report `cli-pool`.
3. Use `--memory-budget` when you need the transfer to size itself against an
   explicit memory bound rather than a detected host/container limit.
4. File destinations using IfAbsent no longer leave a visible truncated final
   after a hard interrupt mid-write.
5. Read [Reflow](../user-guide/reflow.md) and
   [Concurrency and Throughput](../user-guide/concurrency-and-throughput.md)
   for the operator map.

## Library consumers

- `pkg/provider` (**Stable**) is additive: `ResolveConnectionPool`,
  `ConditionalWriteCapabilities` / `ConditionalCapabilityReporter`, and
  optional `Revision` / `RevisionGetter` source-revision reads. Existing
  embedders that do not implement the reporter are treated as unable to prove
  If-Match and are refused fail-closed by `overwrite-if-source-newer`.
- `pkg/reflow` remains **Experimental**. The engine now owns concurrent
  execution, memory admission, collision/durability, provenance sidecars,
  S3-compatible positional sources, and budgeted partitioned work. No Stable
  promotion and no Stable library API break in this cut.
- `pkg/runbudget` (**Experimental**) remains the shared admission substrate
  (including per-domain copy permits).
- Hub consumers should continue to branch on `sqlite-v1` / `durable-v2`
  markers and reject unknown formats.
